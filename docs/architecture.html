Arquitetura

App → SDK (cache + polling) → servidor HTTP → MongoDB ou JSON file. Avaliação de flag acontece localmente no processo da aplicação.

Componentes

SDK

Busca todas as flags na inicialização, mantém mapa em memória e refresca no intervalo de WithEventualConsistency. Diff preserva contadores locais de strategy (QtdCall).

Servidor

Go stdlib net/http. Handlers por domínio, serviços com interfaces Adapter/Publisher, repositórios jsonfile ou MongoDB.

Persistência

REPOSITORY_TYPE=jsonfile (default) ou mongodb. Docker Compose usa MongoDB.

Fluxo de dados

  1. Load inicial — SDK busca todas as flags do project.
  2. Avaliação — app consulta o SDK; resposta vem do cache (sem rede).
  3. Update — API persiste no repositório.
  4. Propagação — cada SDK pega a mudança no próximo poll (eventual consistency).

Quando NÃO usar

  • Precisa de consistência forte imediata em todas as flags
  • Milhares de flags com segmentação avançada / auditoria completa
  • Ambiente sem RAM suficiente para cache do SDK
