Feature Flags

Modelo AP: o SDK cacheia flags do project e atualiza por polling. Mudanças chegam no próximo ciclo de refresh — não há server-push. Você também pode ler e gerenciar flags via HTTP (curl).

Escopo por project. Rotas usam /featureflag/{project}/.... O project deve casar com ^[a-z0-9][a-z0-9-]{0,63}$. Nos exemplos, o token de serviço é service e o do SDK é sdk (valores de SERVICE_CLIENT_AT / SDK_CLIENT_AT).

Rotas

Método & path Descrição Auth
PATCH /featureflag/{project} Cria/atualiza uma flag SERVICE_CLIENT ou login
GET /featureflag/{project}/all Lista todas as flags do project SERVICE_CLIENT ou login
GET /featureflag/{project}/{key} Busca uma flag (session_id opcional) SERVICE_CLIENT ou login
GET /featureflag/{project}/sdk/{key} Leitura booleana (status avaliativo) SDK_CLIENT
DELETE /featureflag/{project}/{key} Remove uma flag SERVICE_CLIENT ou login

API HTTP (curl)

Use estes exemplos para criar, ler e remover flags sem o SDK. Headers Authorization levam o valor cru do token (sem prefixo Bearer).

Criar / atualizar (circuit breaker)

Flag simples on/off, sem strategy. Resposta sem corpo.

Request
curl -i -X PATCH http://localhost:3000/featureflag/checkout \
  -H "Content-Type: application/json" \
  -H "Authorization: service" \
  -d '{
    "flag_name": "checkout_v2",
    "active": true
  }'
Response 204
HTTP/1.1 204 No Content

Criar com percentual (A/B)

50% das avaliações ativas, 50% inativas — útil para rollout gradual.

Request
curl -i -X PATCH http://localhost:3000/featureflag/checkout \
  -H "Content-Type: application/json" \
  -H "Authorization: service" \
  -d '{
    "flag_name": "rollout_50",
    "active": true,
    "strategy": { "percent": 50 }
  }'
Response 204
HTTP/1.1 204 No Content

Criar com session_id

Só as sessões listadas recebem a flag como ativa.

Request
curl -i -X PATCH http://localhost:3000/featureflag/checkout \
  -H "Content-Type: application/json" \
  -H "Authorization: service" \
  -d '{
    "flag_name": "beta_users",
    "active": true,
    "strategy": {
      "session_id": ["34eec623-c9f2-494e-bf66-57a85139fd69"]
    }
  }'
Response 204
HTTP/1.1 204 No Content

Ler uma flag

Retorna o DTO da flag. Header opcional session_id aplica a strategy e reflete o resultado em active.

Request
curl -s http://localhost:3000/featureflag/checkout/checkout_v2 \
  -H "Accept: application/json" \
  -H "Authorization: service"
Response 200
{
  "project": "checkout",
  "flag_name": "checkout_v2",
  "active": true
}

Ler com session_id

Request
curl -s http://localhost:3000/featureflag/checkout/beta_users \
  -H "Accept: application/json" \
  -H "Authorization: service" \
  -H "session_id: 34eec623-c9f2-494e-bf66-57a85139fd69"
Response 200
{
  "project": "checkout",
  "flag_name": "beta_users",
  "active": true,
  "strategy": {
    "session_id": ["34eec623-c9f2-494e-bf66-57a85139fd69"]
  }
}

Leitura via rota SDK

Devolve só o status avaliativo (true/false como string).

Request
curl -s http://localhost:3000/featureflag/checkout/sdk/rollout_50 \
  -H "Accept: application/json" \
  -H "Authorization: sdk"
Response 200
{"status": "true"}

Remover uma flag

Request
curl -i -X DELETE http://localhost:3000/featureflag/checkout/beta_users \
  -H "Authorization: service"
Response 204
HTTP/1.1 204 No Content

Erros comuns

Response 404
feature flag not found
Response 401 / 403
# sem Authorization válido, ou sem acesso ao project (login humano)

Uso no SDK

Instancie com host + project. Listenner bloqueia até o contexto cancelar — rode em goroutine. WithEventualConsistency define o intervalo de refresh. A app avalia flags no cache local (sem rede por chamada).

Go
ff := featureflag.NewFeatureFlagSDK("http://localhost:3000", "checkout").
  WithEventualConsistency(30 * time.Second)

go func() {
  if _, err := ff.Listenner(ctx); err != nil {
    panic(err)
  }
}()

on := ff.GetFeatureFlag("checkout_v2").WithDefault(false)
pct, err := ff.GetFeatureFlag("rollout_50").Err()
beta, _ := ff.GetFeatureFlag("beta_users", sessionID).Err()
