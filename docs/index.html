Dois domínios · um serviço

Escolha o trade-off CAP certo para cada caso.

Feature Flag prioriza disponibilidade. Content Hub prioriza o valor mais fresco. Você usa os dois no mesmo runtime.

AP · Availability

Feature Flag

O SDK mantém cache local e refresca via HTTP periódico. A aplicação sempre recebe uma resposta — mesmo com falha de rede. Ideal para toggles, A/B e rollouts graduais.

CP · Consistency

Content Hub

Conteúdo dinâmico com leitura sempre atual. Estratégias por sessão e balanceamento ponderado para banners, configs JSON e experiências personalizadas.

Por que usar

Feito em Go, para times que fazem ship toda semana.

Latência baixa, disponibilidade alta e um kill switch quando o café não for suficiente.

Kill switch

Desligue uma feature em produção com um PATCH — sem redeploy, sem pânico.

Rollout seguro

Percentual para A/B e session_id para liberar só quem você escolheu.

Cache local

SDK em memória — tipicamente < 10ms. A app responde mesmo se a rede vacilar.

Multi-project

Flags isoladas por project no path. Times e serviços convivem sem colisão de chaves.
